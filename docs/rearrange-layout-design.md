# 整体重排算法设计

状态：树 / DAG / 环及分组均已接入整体重排，等待 Obsidian 界面验收。Portal 适配尚未启用，含传送门的画布会提示并保留原图。

日期：2026-09-11。代码基线：`2a059e7b1edf3723422cecd4074df8faa0a4f6d4`。

关联问题：[多父节点汇入后错位 #4](https://github.com/joeytoday/obsidian-canvas-enhance/issues/4)、[分组内卡片重排后失散 #3](https://github.com/joeytoday/obsidian-canvas-enhance/issues/3)。

## 1. 推荐方案与用户可感知行为

采用「刚性布局单位 + 树形区块布局 + 分层有向无环图布局」。

普通思维导图保持分支上下顺序，每个子树连续排布；多个父节点汇入时，共享卡片只参与一次布局，尽量靠近关联卡片的中心。分组框和内部卡片整体移动，内部排布和尺寸保持原样。拓扑、尺寸与顺序不变时，再次重排不产生新位移。

这仍是现有「整体重排」按钮，不新增模式、设置、持久化分组关系或连线格式。普通树与多父图由算法识别。Tab / Enter 创建卡片、删除后整理同级节点继续使用原有局部逻辑；全图算法不能直接替代它们，否则每次编辑都可能移动整图。

约束的优先级：

1. 节点、原始连线、内容、附件路径、颜色、折叠标记和未知扩展字段完整保留。布局不改变输入数组顺序；折叠结构沿用现有序列化顺序，隐藏成员随所属组输出。
2. 刚性区域内部相对位置和尺寸不变；不同布局单位之间不重叠。
3. 同层上下顺序稳定，重复重排稳定，操作可一次撤销和重做。
4. 在这些约束下尽量紧凑、居中、缩短连线的纵向偏差。

“绝对居中”“无交叉”“连线不穿卡片”不是第一版的硬保证。卡片位置由本插件计算，连线仍由 Canvas 的现有渲染机制处理。

## 3. 输入模型与处理流水线

```text
当前画布与文件身份、选择、视口
  → 深拷贝完整逻辑快照
  → 记录分组几何关系，生成临时布局边
  → 刚性分组区域，收缩后识别环形区域
  → 仅为可测量的非刚性普通卡片计算候选尺寸
  → 按组件选择树形 / DAG 布局
  → 不变量校验，核对输入是否仍有效
  → 一次应用完整结果，恢复选择并展示结果
```

必须在测量改变尺寸前记录分组关系。移动之后再按包含关系找成员，会把新落进框里的卡片当作原成员。

实际接口返回 `rigidGroups`，测量后再次布局时通过 `options.fixedGroups` 复用原始分区，跳过几何重新识别。这也避免组外长卡片因候选高度变大、暂时碰到旧组框而被误吸入。

### 3.1 两套数据，职责分离

- **原始画布数据**：用于最终保存，完整保留字段、数组顺序、原连线端点和存储位置。布局阶段不修改。
- **布局模型**：只有布局单元、尺寸、顺序、临时边、原节点到单元的映射。分组、环收缩仅发生在此模型中。

示意接口：

```ts
type LayoutUnit = {
  id: string
  memberIds: string[]
  originalBounds: Rect
  occupiedWidth: number
  occupiedHeight: number
  rigid: boolean
}

type LayoutResult = {
  positions: Map<string, { x: number; y: number }>
  measuredSizes: Map<string, { width: number; height: number }>
}

// 纯函数：不依赖 CanvasNode、DOM、getBBox、setData 或 requestSave。
function computeLayout(model: LayoutModel, options: LayoutOptions): LayoutResult
```

单元 ID 用无歧义的结构化编码，例如 `JSON.stringify(sortedMemberIds)`，不可简单用 `|` 拼接。原型审查已复现：组 A 包含 B，另有原节点 `A|B` 时，拼接方案产生 ID 冲突。

### 3.2 连线语义

固定连接边沿用 `toSide === 'left'` 的思维导图关系判定。浮动目标边（`toFloating === true`）按保存的 `fromNode → toNode` 参与层级，不依赖此刻的连接边。浮动连线会在导入后自动切换到 top / bottom，若仍按 left 筛选，下一次重排会丢失父子关系并产生新位移。

重排、子节点查找、子树移动和思维导图折叠共用 `isMindmapEdge`，保证自动选边后层级与折叠行为一致。其他固定方向连线仍保留，不承担父子层级约束；不通过箭头样式推断或反转方向。

布局边先校验端点存在，再按 `(fromUnit, toUnit)` 去重。分组或环收缩后再次去重，单位内部的边不参与外层约束。重复连线只影响原画布显示，不增加布局权重；原始边从不删除、反转或改端点。

## 4. 分组、环与折叠

### 4.1 分组作为刚性区域

JSON Canvas 将 group 定义为视觉容器，没有成员 ID 列表。[官方规范](https://jsoncanvas.org/spec/1.0/)

对快照中的每个分组框，找出与其有正面积相交的节点或分组框，通过并查集合并为一个临时区域。普通卡片彼此相交不自动合并。

这条规则同时处理完整包含、嵌套组、部分相交和重叠组。它比只识别严格包含更保守：部分压在分组边上的卡片也一起平移，避免重排改变原有交叠关系。边界仅接触不合并；包含关系本身仍使用现有严格包含语义做验收，不把“移动保护区域”写成新的成员关系。

区域占位取成员几何包围盒，保留原宽高、成员与框的相对偏移。外部布局完成后给区域内每个节点施加同一个平移量。不重新包围成员，也不对组内卡片执行内容自适应。

嵌套组第一版跟随最外部刚性区域整体移动，不递归整理组内内容。大分组可能保留较多空白，这是保留用户内部排版的明确代价。当前为组标签固定预留上方 40px，占位和全图锚点统一包含这段留白，原框尺寸不变。几何成员判定仍只用原框，不用标签或受缩放影响的 live bbox。主题与概览缩放可能放大标签，40px 不保证所有标签样式都不相交，仍需视觉验收。

### 4.2 收缩分组之后再处理环

反例：`A1 → B → A2` 本来没有环，A1 与 A2 同属一个组后会变成 `G → B → G`。

因此，在分组收缩后的图上计算强连通分量（SCC）。含多个单元的 SCC 再收缩成刚性块，内部保持原布局，外部必然得到 DAG。自环保留于原始数据，不参与层级计算。

第一版不重新整理环内部，也不消除其原有重叠。保证的是不同布局块之间不新增重叠。生产版的 SCC / 遍历应使用显式栈，避免数千节点深链造成 JavaScript 递归栈溢出。

### 4.3 折叠使用完整逻辑尺寸

- `mindmapCollapsed` 仅改变显示；隐藏节点仍使用保存的尺寸参与布局。
- 折叠 group 使用保存的完整矩形，隐藏成员随组移动。
- 深拷贝快照后，递归展开尚存的 collapsedData，逐层累加组坐标，按 ID 去重，并保留所有折叠标记。
- 只展开用于计算的数据，不触发 UI 展开，也不为了测量清除折叠状态。

`expandCanvasLayoutSnapshot` 在独立深拷贝中完成展开。较浅层的现存节点 / 边覆盖较深层的陈旧副本；同层等价副本合并，有语义冲突则拒绝布局。唯一隐藏后代以现存父组的绝对位置还原。顶层数组的相对顺序保留，隐藏节点按原存储次序展开，隐藏边追加；不新增持久化成员列表。

这样展开后不会突然挤压其他分支，代价是折叠分支继续占用空间。“折叠时压缩布局”属于另一项功能，不混入此次修复。

## 5. 坐标算法

### 5.1 按弱连通组件分别计算

收缩后的图按弱连通关系分组件。无连线卡片和空组作为单节点组件参与现有“全图整理”语义。

组件先独立计算，最后按原组件包围盒 `(minY, minX, stableId)` 的顺序纵向排列。每个组件的列宽单独计算，避免一张宽卡片撑大所有无关组件的间距。

本轮保留全图统一整理的行为，不提供自动识别笔记区并原地锁定的附加逻辑。独立组件的旧绝对距离不保留，顺序保留。

### 5.2 横向分层

拓扑排序后，以最长路径确定列：

```text
rank(root) = 0
rank(v) = 1 + max(rank(parent))
columnWidth[d] = max(occupiedWidth(v) for rank(v) = d)
x[d + 1] = x[d] + columnWidth[d] + childSpacing
```

共享节点自然位于最深父节点之后。不同列的单位矩形在横向上不相交，不需要 columnEnd 反复修补。

### 5.3 纯树：自底向上的子树区块

弱连通组件中每个节点的不同父节点数最多为 1 时，使用树算法。

```text
childrenHeight(v) = sum(slot(child)) + siblingSpacing × max(0, childCount - 1)
slot(v) = max(occupiedHeight(v), childrenHeight(v))
```

子树顺序来自快照中的上下顺序，以中心 y、x、稳定 ID 消除平局。每个子树拥有连续纵向区块；父卡片位于自身区块中心；孩子的区块整体居中并依次堆叠。每个节点只算一次占位、只得到一个最终位置。

这保留现有普通脑图的分支连续性。边界留白采用精确的 `children - 1` 个间隙，不多算末尾间隙。

### 5.4 多父 DAG：固定顺序的分层约束布局

多父图不再使用“共享子树归哪个父节点”的所有权规则。每个节点只有一个纵向坐标变量，所有父子关系共同影响它。

**层内顺序固定。** 每层按快照中心 y、x、稳定 ID 排序。第一版不自动交换节点来减少交叉。布局结果保持该顺序，下次运行仍读到相同顺序。

**规范初值。** 每层按节点占位高度和间距紧凑堆叠，再以 0 为整体中心，得到 baseline `b(v)`。初值只依赖尺寸、层级和顺序，不依赖上次求解坐标。

**目标函数。** 令 `c(v)` 为单位的纵向中心：

```text
minimize
  Σ edges(u,v) [c(u) - c(v)]²
  + λ Σ nodes(v) [c(v) - b(v)]²

subject to, for every adjacent pair i, i+1 in one layer:
  c(i+1) - c(i) ≥ h(i)/2 + siblingSpacing + h(i+1)/2
```

第一项让相连节点尽量对齐，第二项用一个较小正权重抑制整图自由漂移并使解唯一。当前实现使用 `λ = 0.1`，它是待视觉验收的内部参数，不新增用户设置。

硬约束是层内不重叠与顺序，居中属于优化目标。多个父节点中心为 `0, 10, 100` 时，单纯父边均方目标偏向均值 `36.67`，不是范围中点 `50`；完整目标还受到下游、基线和避让的影响。应将 README 的绝对居中描述改为“共享卡片综合多个关联节点的位置排布，并优先避免重叠”。对称、无冲突的简单汇入仍会居中。

第一版使用单位中心而非每条真实连线端口作为优化目标。组内端点偏离组中心的情况可能产生斜线，但不影响连接关系与不重叠约束。端口感知可在视觉验收后另行评估。

### 5.5 轻量求解：逐层扫描 + 加权单调回归

固定其他层的坐标时，本层每个节点的理想中心和权重为：

```text
q(i) = degree(i) + λ
m(i) = [sum(center(neighbor)) + λ × baseline(i)] / q(i)
```

令 `d(0)=0`，`d(i)=d(i-1)+h(i-1)/2+siblingSpacing+h(i)/2`，再令 `z(i)=c(i)-d(i)`，硬约束变成 `z(i+1) ≥ z(i)`。

对目标 `m(i)-d(i)`、权重 `q(i)` 执行 weighted PAVA（相邻违反顺序的区块合并，取加权均值），恢复 `c(i)=z(i)+d(i)`。每列得到一个满足间距的条件最优结果。正向、反向扫描各层，直到变化足够小或达到确定的轮数上限。

该过程不是不断向下推节点；发生拥挤时会同时调整冲突区块内的节点。每轮为 `O(V+E)`，不需要新增外部布局依赖。有限轮数下只承诺可行的近似解，不能声称每次都已经达到全局最优。

当前实现的停止条件为最大坐标变化小于 `1e-7`，最多 200 轮；后续基于大图和实际视觉效果评估参数。达到轮数上限后仍检查不变量；无效结果不提交。相同输入从相同初值运行相同规则，即使轮数有上限也能稳定输出。

## 6. 重复重排与数值稳定性

不能仅在最后固定根节点位置。当前漂移来自把根 y 和子树顶部混用，应该从计算方式消除。

1. 所有组件先在局部坐标中计算，归一化到自己的包围盒左上角。
2. 使用原布局占位包围盒左上角作为全图平移锚点，包含组标签的固定留白，不使用根节点中心。
3. 组件顺序和每层顺序在输出中被保留；下次读取仍得到同样的顺序。
4. 不使用旧绝对坐标作为 DAG 求解初值。
5. 尺寸有小数时，用向上取整后的宽高作为占位尺寸，原节点尺寸保持不变；间距规范化为非负整数。取整先减去几何容差，避免 `100.00000000000003` 被误扩成 101；正面积相交也使用相同容差，避免零间距的边界接触被误当成重叠。
6. 若输出采用像素对齐，先对局部坐标取整，再加全局锚点。不能先加带小数的锚点再分别取整，否则下一次锚点变化可能导致 1 像素漂移。
7. 刚性区域按单位平移，不单独对组内每个节点取整。原输入含小数时，用小容差判断实际变化，避免浮点尾差产生无意义历史。

独立审查曾在小数尺寸、零间距下复现最终 round 导致单位重叠；占位向上取整与局部取整顺序已补入原型。稳定性承诺的前提是节点拓扑、测量尺寸、间距和用户上下顺序均未改变。首次尚未渲染的内容在下次得出新尺寸，属于输入改变。

## 7. 与 Obsidian 的集成

### 7.1 内容测量只产生计划尺寸

保留普通文字 / Markdown 卡片内容自适应的现有产品行为，但不在测量阶段调用 node.setData。

- 先识别刚性区域，组内与 SCC 内部卡片的原尺寸被冻结。
- 隐藏、未挂载、已断开 DOM、固定宽高比、测量非正数 / 非有限值或挂载超时的节点，使用保存尺寸。
- 宽度固定后测量高度，保留当前 padding、最大高度和 Canvas 最小尺寸限制。
- 初始快照前等待一帧，让已有自动高度任务结算；挂载结束后再等待一帧，然后测量候选高度。任一帧等待超时则取消，不提交。
- 提交前比较完整序列化快照及间距设置，期间有变更即丢弃计划。
- 测量期间临时调整过视口时，失败或取消恢复原视口；用户已手动平移或缩放时保留用户的新视口。

### 7.2 一次提交与一次撤销

计算阶段只修改深拷贝。提交前比较 before/after，没有实际变化时不写入、不增加历史。

实现采用 `overrideHistory() → importData(after, true) → pushHistory(actual) → requestSave(false)`。先结算已有待记录编辑并把当前历史项对齐到 before，再导入完整结果。导入 hooks 可能更新浮动连线的连接边，最终读取 actual 写入历史，保证重做与用户看到的结果一致。

导入时另传一份深拷贝，避免折叠 hooks 原地修改待验证计划。导入后递归展开实际逻辑快照，校验节点数量、全部几何数据、两种折叠标记和原连线 ID / 端点；异常则回滚 before、恢复历史数组与游标，并刷新撤销 / 重做按钮。原生 importData 复用相同 ID 的节点和边，当前选择引用仍然有效，不额外清空选择。

已从本机 Obsidian 1.13.7 提取原生方法，在独立 Node 环境验证无待记录历史、未记录节点编辑、待记录历史、浮动边导入后的撤销和重做。该验证未操作实际画布。CLI 未启用，因此仍需在 Obsidian 界面确认：一次 undo 恢复 before；一次 redo 恢复 actual，包含位置、尺寸、折叠标记和连线。

### 7.3 并发与过期计划

每画布维护一个运行状态，重排期间重复点击不启动第二个任务。提交前检查画布实例、文件身份、只读状态和快照签名。

测量期间发生编辑、拖动、增删连线、切换文件或卸载时，放弃过期计划；不要覆盖新数据。必要时最多从新快照重算一次。最终状态与按钮状态在 finally 中恢复。

### 7.4 Portal 兼容门槛

Portal 投影节点属于其他画布，不应当作当前画布普通节点搬动。`portals-canvas-extension.ts:270–300` 会在 getData 中过滤投影节点，并将跨界边保存在所属 portal 的 `interdimensionalEdges`。

布局约束可将跨界端点临时映射到所属 Portal 文件节点，但保存时保留原端点与原存储位置。不能只看顶层 data.edges，也不能把映射后的边写回。

当前嵌套 Portal 的跨界边往返、异步重新加载后尺寸变化存在待验证边界。一次 setData 同步返回不代表异步 Portal 加载已完成。这轮不顺手重写 Portal 功能；含这类节点的画布必须先通过数据往返与尺寸一致性验收，再启用全量提交。若未通过，应在提交前保留原画布并明确说明该场景暂不可重排。

## 8. 为什么暂不引入通用布局库

标准分层布局把层级、层内顺序、坐标分配和连线路由分开处理。本方案采用这种分工，但限制在本插件当前需要的范围。

| 方案 | 适合程度 | 取舍 |
| --- | --- | --- |
| 修补现有 DFS / ownedShared | 不推荐 | 多父、跨分支和环需要不断添加例外，空间占位仍不清晰 |
| 刚性单元 + 树区块 + 固定顺序 DAG | 推荐第一版 | 约束可解释、可验证，无新增运行依赖；保留部分连线交叉 |
| Dagre / ELK 等通用引擎 | 后续评估 | 更适合交叉优化、端口、递归分组和路由；仍需自行实现数据适配、幂等性及历史事务 |

Dagre 的官方文档将节点尺寸、分层方向、排序 / 坐标与输出边路径作为独立输入输出；ELK Layered 提供端口及跨层级复合图能力。[Dagre 文档](https://github.com/dagrejs/dagre/wiki)、[ELK Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)

当前 Canvas 不消费这些引擎生成的边路径，直接引入库不能自动得到连线避障。待需求确实包括减少交叉、正交绕线、组内递归整理或多方向排版，再评估替换 DAG 内核；快照和提交层仍可沿用。

## 9. 验证结果与实施顺序

### 两批生产实现

布局内核位于 `src/utils/mindmap-layout.ts`，由整体重排入口调用；`npm test` 直接编译并测试生产源码。

- 内核：28 项测试，包含 120 个固定随机种子的 DAG、40 个带环图、50 个带分组图和 5,000 节点深链。覆盖共享下游、跨根 / 跨层汇入、刚性环、嵌套 / 重叠 / 部分相交 / 空分组、固定分区、标签留白、重复边、稳定顺序、小数与零间距、浮动连接边、非法输入及输入不可变性。
- Canvas 适配：22 项边界测试，覆盖组内尺寸冻结、组外高度变化、内容测量、两次 RAF、单次最终历史、重复重排零写入、Portal 保护、并发取消、首帧删空画布、视口保留、失败回滚及浮动连线与折叠语义的一致性。嵌套折叠案例直接调用原有折叠 / 展开 hooks，验证隐藏内容、边、标记及历史数据往返。
- 快照：6 项测试，覆盖递归坐标还原、现存数据优先、同层重复冲突、数组相对次序、源不可变和隐藏 Portal 检测。两批累计 56 项测试通过。
- `npm run build` 生成当前工作区的插件产物；不修改版本号，也不代表发布。
- 独立执行本机原生历史方法验证事务序列；集成测试对 DOM / Canvas 边界使用替身，不能代替 Obsidian 界面验收。

另外以项目真实折叠 hooks 检查内组优先、外组优先、逆序三种节点存储顺序：连续 10 次原始快照往返及 20 次允许 hook 原地修改历史对象的撤销 / 重做，逻辑内容完整且顺序稳定。折叠首次存储会将隐藏成员随组输出，属于现有序列化行为；本批未重写折叠扩展。

仓库全量 TypeScript 检查仍有基线问题（缺少 CodeMirror 模块、设置类型错误），相关文件的 ESLint 仍报告原有 H1 命令的句式问题。这些不是本次改动新增的错误，不扩大本批修复范围。

设计阶段的临时原型已由生产模块及上述回归测试替代，在 1.0.5 发布清理时移除。布局美观性仍需界面验收，不能由不重叠检查替代。

实施分为两批：

1. **已实现，待界面验收**：为 #4 实现纯布局模块与普通节点适配，覆盖树 / DAG、平行边、环、尺寸与重复重排；在 Obsidian 确认一次撤销、内容高度和截图效果。
2. **已实现，待界面验收**：在同一模型上启用 #3 的刚性分组、递归折叠快照及跨组边；覆盖原成员关系、内部偏移、重叠 / 嵌套组和分组收缩后的环。

每批验收通过后再推进下一批。含未完成适配的结构不能退回旧算法继续破坏布局，应在产生任何写入之前保留原图。

### 实机验收清单

| 场景 | 验收重点 |
| --- | --- |
| 普通树与不同高度的长卡片 | 子树连续，父子关系清楚，宽高限制正确 |
| 同级 / 跨分支 / 跨层级汇入 | 共享节点只出现一次、位置合理，原连线不变 |
| 共享节点还有下游或多个汇入点相邻 | 下游不重复占位，层内不重叠 |
| 平行边、自环、纯环与从根进入环 | 不死循环、不丢节点、不反转原边 |
| 嵌套 / 重叠 / 部分相交分组 | 相对位置不变，不新增或丢失成员 |
| 折叠分组与思维导图折叠 | 隐藏卡片不被缩小，展开后布局可用 |
| 两次以上整体重排，零间距和小数尺寸 | 不漂移，不因取整破坏间距 |
| 操作中编辑、拖动、双击按钮、切换文件 | 不覆盖新内容、不留下半完成状态 |
| 一次撤销 / 重做、保存后重新打开 | 完整恢复位置、尺寸、连接与折叠信息 |
| Portal 与折叠组内 Portal | 当前应提前提示，不写入、不测量、不移动卡片；跨界布局仍未启用 |
